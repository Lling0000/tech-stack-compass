# TechStack Compass

一本 AI 时代的产品工程技术栈判断书。

副标题：从第一性原理理解选型、高并发、容灾、从 0 到 1 和那些真实项目里的隐性知识。

这不是资料合集，也不是“技术名词百科”。它是一整本开源书，目标是帮助开发者在真实产品里回答一个更难的问题：

```text
为什么这个场景应该这样选？
为什么现在不应该上那个看起来更高级的技术？
为什么 AI 能写代码，但你仍然要懂技术栈背后的工程判断？
```

## 项目目标

TechStack Compass 的目标是成为中文开发者真正愿意收藏、反复查、持续贡献的高星技术栈知识库。

高星不是靠包装出来的，而是靠内容本身成立：

- 能帮读者在真实项目里做技术判断。
- 每个结论都讲“为什么”，不只讲“用什么”。
- 把隐性知识显性化，让读者少踩生产坑。
- 阅读体验像一本书，而不是零散文档。

## 适合谁

- 用 AI 写代码，但想拥有工程判断力的人。
- 正在从 0 到 1 做 Web、SaaS、AI、App、内部工具的开发者。
- 需要判断“这个项目该用什么技术栈”的产品技术负责人。
- 想补齐高并发、容灾、数据库、队列、上线、监控等工程知识面的人。
- 想知道真实项目里哪些技术“现在不该上”的人。

## 60 秒判断

| 你要做什么 | 默认起步方案 | 第一性原理 | 先别急着上 |
| --- | --- | --- | --- |
| 普通 SaaS / 管理后台 | React/Vue + FastAPI/NestJS/Spring/.NET + Postgres | 主要风险是业务状态和权限，不是极限性能 | 微服务、Kafka、异地多活 |
| AI 应用 / Agent / RAG | Next.js/React + Python FastAPI + Postgres + Redis 可选 + 对象存储 | Python 是 AI 生态入口，慢任务应异步化 | 无评估上线、同步等待长任务 |
| 高并发 API | Go/Java 常见；Python/Node 也能做 I/O 型服务 | 先找瓶颈，很多慢在数据库、锁和外部 API | 只靠多线程解决 CPU 瓶颈 |
| 内容站 / 官网 | Next.js/Nuxt/Astro + Markdown/CMS + CDN | 读多写少，缓存和分发比后端复杂度更重要 | 重后台、复杂数据库设计 |
| 数据分析 / 报表 | Postgres 起步；数据量上来再接 ClickHouse | 先验证查询需求，再引入分析型数据库 | 一开始就复杂数仓 |
| 异步任务 | 数据库任务表起步；稳定后 SQS/RabbitMQ；事件流再 Kafka | 队列只能削峰，不能消灭工作量 | 小任务直接上 Kafka |

## 这本书的写法

每个重要判断尽量遵循同一套结构：

```text
表层说法：大家通常怎么说。
第一性原理：真正约束是什么。
真实选择：在产品项目里应该怎么做。
隐性知识：真实项目里容易被忽略的坑。
```

例子：

| 表层说法 | 第一性原理 | 真实选择 |
| --- | --- | --- |
| Python 不能高并发 | CPython GIL 限制的是单进程多线程执行 Python 字节码，不等于所有 I/O 并发都不行 | Web I/O 可以用 Python；CPU 密集任务用多进程、原生库、队列或拆服务 |
| Redis 能提升性能 | 缓存用一致性和复杂度换速度 | 先确认读瓶颈、过期策略、降级方案，再加 Redis |
| Kafka 更专业 | Kafka 解决事件流，不是普通后台任务默认答案 | 少量异步先用任务表或托管队列，真正需要回放和高吞吐再 Kafka |
| 微服务更可扩展 | 微服务解决组织复杂度，同时引入分布式复杂度 | 0 到 1 先模块化单体，边界清楚后再拆 |

## 推荐阅读方式

如果你时间很少：

1. 读 [一页速查表](./CHEATSHEET.md)。
2. 读 [第 1 章 第一性原理](./docs/01-first-principles.md)。
3. 遇到具体问题再查对应章节。

如果你正在做产品：

1. 先读 [第 5 章 从 0 到 1](./docs/05-product-from-zero-to-one.md)。
2. 再用 [第 2 章 技术栈选择](./docs/02-tech-stack-decision.md) 定栈。
3. 上线前过 [第 6 章 上线清单](./docs/06-launch-checklist.md)。
4. 流量和稳定性开始出问题时读 [第 3 章](./docs/03-high-concurrency.md) 和 [第 4 章](./docs/04-reliability-disaster-recovery.md)。

如果你用 AI 写代码：

1. 用 [第 1 章](./docs/01-first-principles.md) 检查 AI 的技术建议是不是过度设计。
2. 用 [第 7 章](./docs/07-hidden-knowledge.md) 检查 AI 有没有漏掉生产暗坑。
3. 用 [上线清单](./docs/06-launch-checklist.md) 做交付前验收。
