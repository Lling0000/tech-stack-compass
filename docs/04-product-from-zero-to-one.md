# 产品级项目从 0 到 1

目标：用最小可上线版本验证真实需求，同时保留产品级项目必须具备的工程底线。

原则：先跑通核心链路，再补齐稳定性、安全性、可运营性。

## 阶段路线

| 阶段 | 必须做 | 不要做 | 交付物 | 常见坑 |
| --- | --- | --- | --- | --- |
| 问题定义 | 明确用户、痛点、替代方案、成功指标、不做什么 | 不要把“我觉得有用”当需求 | 用户画像、核心场景、成功指标、不做清单 | 痛点太泛，功能堆砌 |
| MVP | 只保留一条核心链路，让用户完成一次完整任务 | 不要把所有边缘场景塞进第一版 | MVP 功能列表、用户流程、验证指标 | MVP 只有功能，没有体验闭环 |
| 技术选型 | 选团队熟悉、生态成熟、可上线的栈 | 不要为了新技术而新技术 | 技术栈说明、架构草图、依赖清单 | 本地能跑，上线困难 |
| 数据模型 | 明确核心实体、关系、唯一约束、状态流转、审计字段 | 不要所有字段塞一张表 | ER 图、表结构、索引、迁移脚本 | 无唯一约束，后期脏数据 |
| 核心链路 | 跑通进入到完成目标的完整流程，处理失败路径 | 不要只测成功路径 | 流程图、API 清单、状态说明 | 用户能打开页面，但任务完不成 |
| 权限/支付/通知 | 后端校验权限；支付处理回调、幂等、对账；通知可重试 | 不要只在前端隐藏按钮 | 权限矩阵、支付状态、通知模板 | 越权、重复扣款、通知失败无人知道 |
| 测试 | 核心逻辑、接口、端到端、权限、异常、边界值 | 不要只靠手动点页面 | 测试计划、自动化测试、回归清单 | 只测快乐路径 |
| 上线 | 生产环境、HTTPS、环境变量、迁移、回滚、监控、日志 | 不要没有备份就迁移数据库 | 部署文档、发布记录、回滚方案 | 上线后没人看日志 |
| 监控 | 可用性、错误率、延迟、数据库、队列、关键业务事件 | 不要只看 CPU | 监控面板、告警规则、错误追踪 | 告警太多没人理 |
| 增长 | 获客、激活、留存、转化、埋点、反馈入口 | 不要只看访问量 | 漏斗、实验计划、反馈记录 | 有流量但没有转化 |

## 产品级最低标准

### 鉴权

- 区分登录态和权限。
- 后端必须校验权限。
- Token 必须有过期时间。
- 支持退出登录。
- 管理员权限必须单独控制。

### 日志

- 记录请求日志。
- 记录错误日志。
- 记录关键业务事件。
- 日志必须包含请求 ID。
- 日志不能包含明文密码、Token、身份证、银行卡等敏感信息。
- 日志必须能定位用户、时间、接口、错误原因。

### 错误处理

- 前端显示可理解的错误提示。
- 后端返回统一错误结构。
- 区分用户错误和系统错误。
- 第三方服务失败要有降级方案。
- 关键操作失败要可重试。
- 错误必须可追踪。

### 配置

- 配置和代码分离。
- 使用环境变量管理密钥。
- 区分开发、测试、生产环境。
- 生产配置不得提交到仓库。
- 关键配置要有默认值或启动校验。

### 迁移

- 数据库结构变更必须走迁移脚本。
- 迁移前必须备份。
- 重要迁移要支持回滚或补偿。
- 生产迁移要记录时间和操作者。
- 不要直接手动改生产表结构。

### 备份

- 生产数据库必须定期备份。
- 备份必须验证可恢复。
- 关键文件必须备份。
- 备份要有保留周期。
- 备份权限要受控。
- 备份数据也要保护隐私。

### 监控

- 监控可用性。
- 监控错误率。
- 监控响应时间。
- 监控数据库。
- 监控关键业务指标。
- 告警必须有人负责处理。

### CI

- 每次提交自动运行测试。
- 自动检查代码格式。
- 自动检查类型或构建。
- 自动阻止失败构建发布。
- 发布流程可追踪。
- 生产发布需要明确版本号。

### 文档

- 项目启动说明。
- 环境变量说明。
- 部署说明。
- API 文档。
- 数据库结构说明。
- 常见问题说明。
- 故障处理说明。

### 安全

- 使用 HTTPS。
- 密码必须哈希存储。
- 防止 SQL 注入。
- 防止 XSS。
- 防止 CSRF。
- 上传文件要校验类型和大小。
- 接口要限流。
- 管理后台要加强保护。

### 隐私

- 明确收集哪些数据。
- 明确数据用途。
- 最小化收集用户数据。
- 敏感数据加密或脱敏。
- 支持用户删除或导出数据。
- 第三方服务要检查隐私风险。
- 日志和埋点不能泄露隐私。

## 不同项目类型的坑

### SaaS

- 多租户数据隔离不清。
- 用户越权访问其他团队数据。
- 订阅状态和权限不同步。
- 免费版、试用版、付费版边界混乱。
- 发票、退款、取消订阅流程缺失。
- 管理后台无法处理真实运营问题。
- 没有用量统计，无法做套餐限制。
- 没有审计日志，企业客户不敢用。

### Web

- 首屏加载过慢。
- SEO 没有基础配置。
- 移动端体验差。
- 表单校验只做前端。
- 路由权限保护不完整。
- 静态资源缓存策略错误。
- 图片未压缩。
- 页面刷新后状态丢失。
- 错误页面缺失。

### App

- 没有处理弱网和离线状态。
- 没有适配不同屏幕尺寸。
- 推送权限滥用。
- 包体过大。
- 启动速度慢。
- 本地缓存没有过期策略。
- 后端接口变更导致旧版本崩溃。
- 应用商店审核材料准备不足。

### AI 项目

- 没有限制输入长度。
- 没有控制调用成本。
- 没有处理模型幻觉。
- 没有敏感内容过滤。
- Prompt 写死且不可版本管理。
- 没有记录模型版本。
- 没有兜底回复。
- 没有流式输出体验。
- 没有评估集，无法判断效果变好还是变差。
- 用户数据直接进入第三方模型，隐私风险高。
- RAG 检索结果不准确。
- 没有防止 Prompt Injection。
- AI 输出直接执行高风险操作。
- 关键场景没有人审机制。

## 一条真实的 0 到 1 路线

1. 写清楚目标用户和一个核心痛点。
2. 写不做清单，防止范围膨胀。
3. 选一套团队能维护的栈。
4. 建核心数据模型，不要过度抽象。
5. 跑通一个核心链路。
6. 处理空状态、加载状态、错误状态。
7. 做后端权限校验。
8. 给关键操作加幂等。
9. 接日志、错误追踪和基础指标。
10. 写部署文档和回滚方案。
11. 小流量上线。
12. 看真实用户行为和失败点。
13. 根据证据迭代，不根据想象堆功能。
